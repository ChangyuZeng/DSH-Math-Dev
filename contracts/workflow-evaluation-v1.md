# 固定模型 workflow 评测契约 v1

状态：预注册协议草案；没有实验结果，没有启动研究。实现可执行、工程可靠与数学有效是三个分别验收的命题。本契约不预设 workflow 优于基线。

## 冻结比较条件

每个配对单元固定同一问题精确版本 `problem_ref={id,rev}`、相同初始材料及材料哈希、同一 provider/model 的明确版本、相同 effort、请求上限、总 token 上限、单次输出上限及上下文 token 上限。记录实际可解析模型版本、服务端默认参数、采样参数、可用 seed、日期和运行环境；不可解析的别名版本标记未知。不得在某一臂悄悄换模型、提高 effort 或补充材料。

执行前保存不可变 `dsh-math-workflow-v1` spec：`project_id`、`problem_ref`、`model_policy:{provider,model,effort}`、`budget:{requests,total_tokens,max_output_tokens}`、`tools`、`context_budget:{max_tokens}`、`stage_goal`。所有预算为有限正整数。工具集合、提示模板及哈希、上下文选择/裁剪策略、停止条件、失败处理和最终产物提取规则也必须冻结；本版 UI 的 `tools` 为 `[]`。调整方案必须另建版本，不能覆盖已运行条件。

| 臂 | 处理 | 明确边界 |
| --- | --- | --- |
| B0 direct | 一次直接求解，产出最终候选 | 同一总预算上限，实际只用一次请求，不能暗中追加修订。单次输出上限与其他臂相同。 |
| B1 loop | 固定模型的通用检查与修订循环 | 冻结循环提示、最大次数、停止策略及传递上下文；不使用 W1 的结构化 obligation 状态。 |
| W1 obligation | 固定模型围绕待证事项执行 derive/check/revise/decompose 等动作 | 冻结动作选择策略、精确依赖、候选登记及停止规则；持久化记录不能被算作数学正确性。 |

相同预算指相同可用上限，不要求各臂烧完预算。B0 的一次请求限制是实验因素，必须同时报告实际消耗、预算利用率与质量。不能将 B0 未使用的预算作为其“失败成本为零”的依据。若另设等实际消耗比较，应提前定义独立分析，不用事后挑选的轮数替换主比较。

## 配对重复与盲评

先固定问题总体、纳入/排除规则、难度分层、重复次数和统计方案，再运行。每个问题及重复编号形成 B0/B1/W1 配对单元；交错或随机化执行顺序，记录服务变更与时间效应。可用 seed 时成对记录；不支持 seed 时报告该限制。禁止用最优一轮代替全部重复，禁止只保留成功问题。

盲评包隐藏臂名、内部动作日志和过程提示，对最终候选使用统一格式和随机标识，保留可审核的数学内容与来源。事先定义评审量表、独立评审人数、冲突仲裁和缺失判定规则。分析以问题为单位处理相关性，报告成对差异、区间和重复波动；不把同一问题的多轮调用当作独立问题。样本量及统计方法待实验负责人预注册，此文不填造数字。

## 工程与数学指标分别报告

工程指标包括：spec 冻结、权限拒绝是否生效、CAS 冲突检测、operation_id 幂等性、恢复后 unknown 保留、续接的 parent/research head、输出与依赖版本可追溯、上下文截断可见性、预算执行、调用失败率、持久化和刷新失败。工程通过不能替代数学评审。

数学指标包括：最终答案正确性、证明完整性、关键缺口严重程度、无依据断言、条件适用性、局部结论范围、反例有效性及独立人工接受。待证事项数量、模型自评分、程序检查通过率、流程 completed 均不能直接计为全局证明。`candidate_pending_review` 保持候选意义；既有 `local_claim`、R1/R2 与正式人工审核边界继续适用。评审发现的关键缺口必须附定位与理由。

## 计量、失败和停止

逐请求记录 request/action/run 标识、尝试时间、provider/model/effort、上下文来源及估算方式、输入/输出/缓存/reasoning usage（若服务提供）、请求状态、错误、输出哈希及引用、耗时和可核实费用来源。总 token 的统计口径应与实际预算执行口径一致并公开，不能把缓存 token 抹掉。不能重复累加供应商总计与其子项。

缺失 usage 标为 unknown/incomplete；未知不等于零，不能假造 token 数、价格、推理 token 或缓存命中。另报计量完整率、可计量子集及缺失模式；如果缺失可能改变成本结论，成本比较标记不可判定，或使用预先定义且明确标注的保守界限。

超时、取消、无效输出、校验失败、权限拒绝、失败修订及续接均保留。实际已发出的失败请求计入请求预算；已有 usage 计入成本；未知成本单列。失联后不自动重试，先 reconcile；unknown 请求可能已经消耗额度，不能以新 run 掩盖失败成本。续接必须保留 parent、原始条件和研究 head，累计成本分析跨续接链追踪。重试策略若进入后续版本，必须预先冻结且所有尝试计量。

报告预算耗尽、正常停止、基础设施失败及人工停止的数量和原因，不把停止原因混为数学失败。实际开展研究仍需独立显式授权；UI 测试不得调用真实模型。

## 外部方法与结论边界

ProofLoop 目前未核实：尚无经过核验的论文版本、方法定义、实现、授权许可及可比配置。本契约中的 B1 是本地通用 loop 基线，不能称为 ProofLoop 复现，也不能报告相对 ProofLoop 的优势。只有完成原始来源与实现核验后才能新增对应比较臂，并记录差异与版本。

验收报告须分别列出工程验收结果、数学盲评结果、实际成本与缺失数据。实验未运行时保留“未运行”；证据不足时保留“不可判定”，不将功能实现或少量示例包装为研究优势。
